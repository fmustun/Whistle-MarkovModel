# Whistle-MarkovModel

Markov-chain and network analysis of dolphin whistle sub-categories for
*Whistle Variability and Social Acoustic Interactions in a Small Pod of
Bottlenose Dolphins* (Mustun, Semenzin et al.): significant-transition
network, community structure, node roles, and multi-loop analyses.

Whistle extraction, sub-clustering and the ancestral-whistle DTW matching
(Fig. 6) are not part of this repository; the extraction code is at
<https://github.com/zebrain-lab/Dolphins>.

## Requirements

## Parameters

All defaults are in [R/config.R](R/config.R), including:

- `TIME_WINDOW = c(0, 5.94)`: maximal inter-whistle interval within a sequence.
- `NULL_MODEL = "shuffle"`, `ITERATIONS = 150000`, `SEED = 0`.
- `MULTIPLE_TESTING_CORRECTION = "BH"`, `GRAPH_ALPHA = 0.05`.
- `MULTILOOP_IWI_THRESHOLD = 0.25`: inter-whistle interval (s) grouping
  whistles into a multi-loop chain (Esch et al. 2009).
- `MULTILOOP_CLUSTER_*`: Needleman-Wunsch costs and linkage for the
  composition clustering.
- `COMMUNITY_RESOLUTION = 0.5`: Leiden resolution, chosen from script 03b.

### Significance testing and `ITERATIONS`

The one-sided empirical p-value of each transition is
`(1 + count(null >= observed)) / (B + 1)`. BH correction is applied only to
transitions observed at least once (m = 1,214), since a never-observed
transition can never be retained (`family_mask` in
`adjust_transition_p_values()`, [R/statistical_utils.R](R/statistical_utils.R)).

The p-value floor is `1 / (B + 1)`, so BH at `GRAPH_ALPHA` needs
`B >= m / GRAPH_ALPHA - 1` to resolve anything at all.
`recommended_iterations(m, alpha, margin = 5)` adds a safety margin
(about 121,400 for m = 1,214); the manuscript run uses 150,000. Derive
`ITERATIONS` from this bound rather than tuning it until the network "looks
right". Script 01 is CPU-intensive (parallel null model); with 150,000
iterations, expect a long run.

The secondary networks (scripts 08 and 10) derive their own iteration counts
from their own number of observed transitions with the same function.
